SMART SHOPPING ASSISTANT - PROJECT REPORT

1. IMPLEMENTATION DETAILS

1.1 Overall Architecture
- The system is implemented as a web application with a Flask backend and both template-based UI and a React-based frontend module.
- Backend entry point: backend/app.py
- Backend templates/static assets served by Flask from:
  - frontend/templates/
  - frontend/static/
- Additional React app (Create React App structure) located in frontend/src/ and managed with npm scripts.

Image placeholder: High-level architecture diagram showing Browser -> Flask App -> SQLite Database and React module.

1.2 Backend Implementation (Flask + SQLAlchemy)
- Framework: Flask (Flask==2.3.3)
- ORM/Database: Flask-SQLAlchemy with SQLite database products.db
- Security helpers: Werkzeug password hashing (generate_password_hash, check_password_hash)
- NLP/Sentiment: NLTK VADER SentimentIntensityAnalyzer

Core backend responsibilities:
- User authentication and session handling:
  - /register, /login, /logout
  - Passwords stored as hashes (not plaintext)
- Product simulation and scoring:
  - Mock products generated dynamically (price, rating, eco score, safety score, reviews)
  - Unified score computed from weighted cost, quality, safety, and eco factors
- External e-commerce API status:
  - APIs from e-commerce websites are not yet integrated in the current implementation.
  - Product data shown after user search is currently generated through internal mock logic.
- Utility APIs:
  - Favorites management API
  - Search history API
  - Budget calculator API
  - Sentiment analysis API
- Search and comparison workflows:
  - Product search with filters and sorting
  - Side-by-side product comparison
  - Recommendations and deals pages

1.3 Data Model
- User model includes:
  - id, username, email, password, created_at, favorites
- Product model includes:
  - id, name, price, rating, reviews, ingredients, eco_score, safety_score, category, description
- SQLite is used for persistence, and db.create_all() initializes schema on startup.

Image placeholder: Entity diagram showing User and Product fields, with session-based favorites relationship.

1.4 Frontend Implementation
- Flask-rendered pages for core flows:
  - index, results, compare, deals, recommendations, favorites, login, register
- Separate React frontend module includes components for:
  - authentication (Login, SignUp)
  - product operations (AddProduct, ProductList, UpdateProduct)
  - route protection (PrivateComponent)
- React dependencies include react-router-dom and testing-library packages.

Image placeholder: UI flow screenshot panel showing Home -> Search Results -> Compare -> Favorites.


2. SYSTEM FEATURES

2.1 Product Discovery and Evaluation
- Product search by query input (currently returns internally generated mock product data).
- Filter support: price range, minimum rating, minimum eco score, category.
- Sorting support: unified score, price (low/high), rating, eco score.
- Unified scoring algorithm combines:
  - cost efficiency
  - quality (rating + review sentiment)
  - safety score
  - eco score

Note: Real-time product fetch from external e-commerce platforms is planned for future integration.

2.2 Product Comparison
- Users can select multiple products and compare them side by side.
- Comparison includes pricing, rating, eco and safety related metrics, and unified score.

2.3 Personalized Utility Features
- Favorites add/remove endpoints and favorites page.
- Search history tracking with a capped recent-history list.
- Budget calculator returns products within budget plus savings insights.

2.4 Recommendation and Deals
- Recommendation page for similar products.
- Deals page with discount-based sorting and stock indicators.

2.5 User Management and Access Control
- Registration and login with validation.
- Password hashing for basic credential safety.
- Route protection using a login-required decorator for controlled access.

3. TESTING AND VALIDATION

3.1 Current Testing Setup
- Frontend has Create React App testing setup:
  - frontend/src/setupTests.js configures jest-dom
  - frontend/src/App.test.js exists as a starter test
- Backend dependencies are configured for runtime; dedicated backend unit test files are not present in current structure.

3.2 Validation Performed in Application Logic
- Input validation in authentication flow:
  - required fields, username length, password length, password confirmation
  - duplicate username/email checks
- API-level validation examples:
  - budget must be positive in budget calculator
  - compare route validates selected IDs
  - search route handles empty query
- Session state validation:
  - guarded behavior for favorites/search history initialization

3.3 Functional Validation Scope (Recommended Checklist)
- Authentication:
  - valid and invalid login/register attempts
- Search and filters:
  - query, filter boundaries, sorting correctness
- Comparison:
  - minimum selection handling and result consistency
- Favorites and history:
  - add/remove behavior and persistence during session
- Budget and sentiment APIs:
  - JSON response format and edge-case values

3.4 Observations
- The existing App.test.js is a default CRA sample test and may require update to match the current App UI routes/components.
- For stronger confidence, add:
  - backend unit tests for scoring and route responses
  - integration tests for end-to-end user flows
  - API contract checks for JSON endpoints

4. DEPLOYEMENT AND MAINTENANCE

4.1 Deployment Strategy
- Local run procedure:
  - Install backend dependencies: pip install -r backend/requirements.txt
  - Run Flask app: python backend/app.py
  - Access at http://localhost:5000
- React module can be run independently for frontend development with npm start.

4.2 Production Deployment Recommendations
- Replace development server with production WSGI server (for example Gunicorn on Linux-based hosting).
- Use environment variables for secret key and sensitive settings.
- Move from SQLite to a production-grade database if concurrent multi-user load increases.
- Configure reverse proxy (for example Nginx) and HTTPS.

4.3 Maintenance Plan
- Preventive maintenance:
  - dependency updates and security patching
  - log monitoring and periodic backups
- Corrective maintenance:
  - bug tracking from user feedback
  - test-based regression fixes
- Perfective maintenance:
  - improve recommendation quality
  - expand real API integrations (product catalogs and review sources)
- Adaptive maintenance:
  - accommodate new categories, changing market behavior, and UI improvements

4.4 Operational Checklist
- Maintain version control workflow per branch strategy.
- Run smoke tests after every major change.
- Monitor response time and server health metrics.
- Maintain database backup and restore process.

CONCLUSION
The Smart Shopping Assistant is implemented with a practical full-stack structure using Flask, SQLAlchemy, SQLite, and React assets. It delivers core shopping-assistance capabilities (search, ranking, comparison, recommendations, and budgeting) with user authentication and session-based personalization. To improve production readiness, the next priority areas are formalized automated tests, secure production configuration, and a scalable deployment stack.
